- Phase 3/8: homepage bulk-enquiry banner, footer and admin shell must be white surfaces with bordered/accent components (the Stitch navy banner and gray admin canvas are not used).

## Decisions on Phase 7: Admin Authentication & Authorization (2026-11-20)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 22  | Admin identity & authorization: Supabase Auth SSR via `@supabase/ssr` (`createBrowserClient`, `createServerClient`, `createSupabaseProxyClient`). Single-administrator v1 model with manual provisioning. Explicit `admin_profiles` table linked to `auth.users(id)` and `is_active = true`. Missing or inactive admin profile denies access (fail closed). No public signup or registration routes.                  |
| 23  | Multi-tier defense-in-depth authorization: (1) `proxy.ts` performs optimistic redirection and session cookie refresh; (2) `(console)/layout.tsx` verifies admin session server-side; (3) every Server Action and protected Route Handler independently checks administrator authorization via `requireAdmin()` / `withAdminAction()`; (4) database Row Level Security enforces authorization via `public.is_admin()`. |
| 24  | Layout separation: Route-group split under `src/app/admin/` into `(auth)` (clean centered card without sidebar) and `(console)` (sidebar with navigation and sign-out button). Request-time dynamic rendering enforced with `await connection()` under Next 16 `cacheComponents`.                                                                                                                                     |

## Decisions on Phase 8: Admin Dashboard, Catalogue Management & Website Experience (2026-11-20)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 25  | Admin Dashboard Architecture: `loadAdminDashboardData()` aggregates snapshot data from Google Sheets (active/inactive products, categories, brands, data validation issues) and enquiry metrics from Supabase PostgreSQL (counts by status and latest 10 rows). Graceful error degradation is implemented so that upstream failures log warnings and render empty states rather than crashing the console.        |
| 26  | Catalogue Mutation & Concurrency: All admin catalogue modifications (create, update, toggle active) execute via Server Actions wrapped with `withAdminAction()`. Updates require `expectedUpdatedAt` timestamp verification to guarantee optimistic concurrency locking. Mutations directly target Google Sheets rows and invalidate the cache atomically via `invalidateSheetsCache()`.                          |
| 27  | Dependency Protection for Categories and Brands: A single unified `/admin/categories` interface provides tabbed category and brand management. Deactivation of any category or brand is strictly blocked with a descriptive user message if active products currently reference it, preventing orphan or invalid catalogue states.                                                                                |
| 28  | Multi-Page Website Navigation & Carousel Discovery: The public website navigation was reordered to `Home`, `Products`, `Contact`, `Bulk Enquiry`. The homepage carousel is data-driven with local image discovery; when local images are pending in `public/images/carousel/`, it renders an architectural Deep Navy (`bg-primary`) SVG pattern fallback without broken image tags, layout shift, or token leaks. |
